9. Audit method, history and reproducibility
============================================

obligation_map.json is a finite map of sufficient conditions.
An AND node requires all its listed inputs on the compatible
objects specified in its premise. An OR node records complete
alternative sufficient routes. Theorem antecedents are kept
distinct from claims proved by the implication. Related-node
annotations and source continuation anchors are not proof
edges. The map is not an exhaustive transitive Lean graph,
a proof of necessity, or a completion-percentage measure.

All 111 v0.27 node identities are preserved. Every changed
node stores its complete immediately preceding record,
including previous history, and the entire old map is
copied byte-for-byte as previous_obligation_map.json. The
current validation count is computed from the current
nodes; historical validation records are left unchanged.
Only DA26-SP-04 and DA26-SP-06 are proposed for retirement.
The catalogue compound target is narrowed explicitly and
ImageDense, the actual remaining counts and global targets
are preserved.

source_anchors.json verifies every indexed full source blob
against the pinned Git object, and every cited range against
its exact bytes. Each new component main text and every
proof range is hash-checked. input_manifest.json binds the
actual component files, the unchanged prior input manifest,
the applicable mathematical reviews and the integration
configuration. Downstream semantic/final-scope/coverage/
package outputs are excluded from this manifest to avoid
circular hash dependencies. The independent semantic
review can bind these finished audit files afterwards.

These provenance and graph checks establish reproducible
bookkeeping, not mathematical truth by themselves.
Independent mathematical reviews bind the frozen proof
texts separately. Draft-mode TeX checks syntax, fonts and
references; no new PDF or Lean kernel replay is claimed.
