1. OVERALL ASSESSMENT

A substantial amount can be done in parallel. There is enough independent
work remaining to keep all four currently available agents productively
occupied: three subagents alongside the coordinating agent.

Maintain a queue of roughly 8–12 precisely scoped proof and review
assignments, drawing from the different branches of the roadmap. This is
a scheduling judgment, rather than a measured optimum or a prediction of
speedup. The current execution capacity is four active agents in total;
the larger queue supplies replacement tasks as workers finish or encounter
a dependency.

The main constraint is that several arguments must ultimately use the same
mathematical objects, choices, and normalizations. Agents can develop the
component theorems concurrently, but combining their conclusions requires
careful coordination.

The v0.49 baseline has 24 open whole obligations: 17 shared by RH and
Dirichlet GRH, plus seven additional obligations for Dirichlet GRH. These
obligations vary greatly in size and share inputs, so their number is not
a count of independent jobs. The breakdown below follows the updated
v0.49 roadmap [1].


2. WHERE PARALLEL WORK IS AVAILABLE

2.1. Common automorphy datum

Parallel work:
  • Compatible field and frame construction.
  • The universal linked-end theorem.
  • Local compatibility and descent arguments.

Combination requirement:
  The conclusions must apply to one compatible frame, coefficient embedding,
  and marked element g_1, and return the exact original automorphy statement.

2.2. CountV

Parallel work:
  • The host/frame/length dictionary.
  • The two cohomological transport arguments.
  • The uniform representation catalogue.
  • The remaining rank-three support theorem.

Combination requirement:
  All of these must be installed on the same actual host data before the
  CountV conclusion follows. Some upstream automorphy work is shared with
  the preceding area and should be assigned once.

2.3. Framed geometry and test rings

Parallel work:
  • Descent to all required test rings.
  • Normalized frame construction.
  • Covering and fiber arguments.
  • Several spanning and class-sum arguments.

Combination requirement:
  The results must refer to the same moduli objects, models, sections,
  frames, and readings.

2.4. Actual local specialization

Parallel work:
  Different arithmetic, coefficient-field, valuation, and spectral
  ingredients can be reconstructed at their stated interfaces.

Combination requirement:
  The full local input must be realized on the common family, with the
  required field identifications and compatibility.

2.5. Analytic arguments

Parallel work:
  • Bessel nonvanishing.
  • Orbital and fiber comparisons.
  • Measure and normalization identities.
  • Relevant counting arguments.

Combination requirement:
  The applications must use the same representations, characters, Haar
  measures, and global analytic setting.

2.6. Four remaining global estimates

Parallel work:
  Denominator, retained-defect, period-height, and spectral arguments can
  be developed separately where their original hypotheses are supplied.

Combination requirement:
  The estimates must all hold for the actual common family, with the
  correct order of constants, thresholds, and subsequent choices.

2.7. Additional Dirichlet-GRH branch

Parallel work:
  • Seed construction.
  • Tensor-factor towers.
  • Rank-four propagation.
  • Residual descent.
  • The chain-reduction implication.

Combination requirement:
  The potential-modularity and automorphy joins require these inputs
  together, with compatible residual and tower data.

2.8. Human exposition and independent review

Parallel work:
  • Review completed proof packets.
  • Consolidate notation.
  • Write explanatory sections whose mathematical interfaces are stable.

Combination requirement:
  The final manuscript needs a consistent statement of every dependency
  and a complete route to the terminal conclusions.

Several of these areas contain more than one useful assignment. Together
they support a rolling queue of 8–12 bounded tasks without treating the
24 open obligations as equally sized or mutually independent projects.


3. PROVING A THEOREM VERSUS CONSTRUCTING ITS INPUTS

This distinction allows more parallelism than a simple dependency diagram
might suggest.

Suppose one part of the proof must construct data D satisfying P(D).
Other agents can simultaneously prove:

  For every D, P(D) implies A(D).

and:

  For every D, P(D) implies B(D).

Those proofs can be completed before the construction of D is finished.
Once the construction is available, both theorems apply to that same D.

By contrast, independently obtaining

  There exists D such that A(D),

and

  There exists D such that B(D),

does not establish

  There exists D such that both A(D) and B(D).

This matters repeatedly in the reconstruction: the common bundle, the
arithmetic frame, the coefficient field, the theta readings, the host data,
and the global estimates all have places where the same choice is essential.

A conditional theorem can therefore be a completed mathematical contribution
while its application still awaits a compatible input construction. The
record of progress must preserve that distinction.


4. CONCRETE EXAMPLE: THE ARITHMETIC BRANCH

The pinned source supports the following division:

  1. One agent constructs the compatible arithmetic frame and seed data.

  2. Another reconstructs LinkedEndEAlt, which is stated universally for
     supplied frame/link/seed data satisfying its hypotheses.

  3. Another reconstructs the local compatibility and descent inputs.

  4. The components are combined, and the resulting conclusion is checked
     against the exact original automorphy endpoint.

The universal form of LinkedEndEAlt is what permits its proof to proceed
alongside frame construction. The subsequent dependency theorem combines
frame existence, linked-end information, and descent inputs. The relevant
source statements are in PlDefs.lean and GdEndOf.lean [2, 3].

There is also an opportunity to avoid duplicated work: a common upstream
argument supplies both an alternative automorphy end datum and a core
CountV support theorem. That argument should have one owner, after which
the two exact endpoint reconstructions can proceed separately. This shared
dependency is explicit in DnEnds.lean [4].

The shared upstream result does not by itself supply either whole original
endpoint. Each branch still requires its exact return to the original
statement.


5. RECOMMENDED USE OF THE FOUR AVAILABLE AGENTS

5.1. Arithmetic agent

Initial responsibility:
  One bounded component of the common automorphy construction or its shared
  CountV support.

Required handoff:
  A complete human proof with the exact field, frame, seed, and choice-order
  requirements stated.

5.2. Geometry agent

Initial responsibility:
  One producer needed for all-test-ring geometry, normalized frames, or the
  common readings.

Required handoff:
  A complete proof referring to the original models and sections, with its
  remaining input hypotheses explicit.

5.3. Analysis agent

Initial responsibility:
  Bessel nonvanishing or a specific analytic comparison needed downstream.

Required handoff:
  A complete argument with the representation parameters, measures, and
  normalization factors fixed.

5.4. Coordinating agent

Initial responsibility:
  One remaining global estimate or a concrete compatibility theorem,
  together with maintaining the shared interfaces and integrating completed
  work.

Required handoff:
  A substantive proof contribution and a checked account of how the
  independently produced components fit together.

This allocation gives each worker actual mathematical work. Coordination
should remain small enough that the coordinating agent can continue proving
a component as well.

Assignments should be dynamic. When a worker finishes a packet, it can:

  • Review another worker's completed packet.
  • Take a bounded CountV transport or catalogue task.
  • Start an additional Dirichlet-GRH producer.
  • Continue the next dependency in its existing branch.

There is no need to wait for all four branches to finish a large round
before reviewing and integrating the first completed result.


6. KEEPING THE FULL GRH OBJECTIVE MOVING

The additional GRH branch offers useful independent work. Seed construction,
tensor-factor construction, chain propagation, and descent need not all wait
for the shared RH work to finish.

The chain-reduction implication can also be reconstructed while its seed
input is being produced, provided that input remains an explicit hypothesis.

The two later Case-III joins are natural combination points. This division
is recorded in work package R of the roadmap [1].

With four workers, rotate a worker into this branch when a suitable proof
packet finishes. If more workers become available, this is one of the first
areas that should receive a dedicated assignment.


7. WHAT MUST REMAIN COORDINATED

7.1. Shared choices and quantifiers

Before assigning related tasks, record the precise interface:

  • Which objects are fixed?
  • Which objects may the agent construct?
  • Which choices must precede all later parameters?
  • Which constants must be uniform?
  • Which normalizations and identifications are required?

For example, a bound with a constant depending on each subsequently chosen
host does not replace a theorem requiring one constant chosen before all
those hosts. A pointwise existence result may therefore be insufficient even
when its mathematical content looks close to the target.

A short, fixed interface statement prevents large amounts of incompatible
work.

7.2. Common-family assembly

The construction of one family on which all the required conclusions hold
is a real mathematical task. Several of its ingredients can be proved
concurrently, and even its assembly theorem can be written with its
antecedents explicit. Its instantiated conclusion is available only after
the required ingredients have been supplied compatibly.

The same applies to the final CountV and Case-III joins.

7.3. Independent review and final exposition

Review can overlap with new proof work. Once an author freezes a proof
packet, another agent can review it while the author starts an independent
task.

The final exposition also permits parallel drafting, but it needs a common
notation and theorem dictionary. A final editorial pass must check that
the resulting document presents a continuous human argument, with every
dependency either proved or explicitly identified.


8. WHAT CAN BE SAID ABOUT TIME SAVINGS

Four active workers are justified by the available work. A particular
speedup or percentage of parallelizable effort is not yet justified by
the evidence.

The usual scheduling bound makes the limitation clear. Let:

  W   = the total work, measured using a consistent unit;
  L   = the work along the longest chain of dependent tasks;
  p   = the number of workers;
  T_p = the completion time with p workers.

Then the idealized lower bound is:

  T_p >= max(W / p, L).

Parallel work reduces the first constraint. It cannot eliminate the
dependency chain, and review, communication, and interface corrections
add further time.

For this project, the useful scheduling objective is to shorten the longest
remaining dependency chains while keeping the other workers busy on
independent producers and reviews. Counting claims or assigning one agent
to each of the 24 open obligations would not measure that effectively.


9. RECOMMENDED EXECUTION POLICY

Use all four available agents. Maintain a rolling queue of 8–12 exact
assignments. Give shared upstream arguments a single owner. Rotate
independent review as packets finish. Keep all shared objects, quantifier
orders, and normalization conventions explicit at the interfaces.

This exploits the substantial parallelism in the remaining reconstruction
while preserving the compatibility needed for a complete human-readable
proof.

This document records the parallel-work plan at baseline v0.49. It introduces
no new proof claims and does not change the status of any obligation.
